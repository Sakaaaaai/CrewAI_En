# Section 5 Exercise 5-3 | Managing State

## Goal

Manage a Flow's **state** with type safety using a Pydantic model.
Learn that a Flow can hold "memory" by **accumulating a counter and history across multiple steps**.

## What you'll learn in this exercise

### state is a Flow's shared notepad

In 5-2, you passed data along via return values. But for "data you want shared across every step," passing it through arguments every time gets tedious.
That's where **state** comes in. It's a shared notepad that any step can read and write via `self.state`.

### Defining a typed state

Deciding the shape of the state with a Pydantic model guarantees field names and types, keeping things safe.

```python
from pydantic import BaseModel

class CounterState(BaseModel):
    counter: int = 0
    history: list[str] = []

class CounterFlow(Flow[CounterState]):   # <- [CounterState] specifies the type of the state
    ...
```

### Readable and writable from any step

```python
@start()
def step_one(self):
    self.state.counter += 1              # freely readable/writable
    self.state.history.append("step_one")
```

Specifying the type as `Flow[CounterState]` makes `self.state` an instance of `CounterState`,
starting from its default values (`counter=0`, `history=[]`).

## Common errors

- `counter stays at 0` → You forgot the `Flow[CounterState]` type specification, so state isn't being initialized
- `AttributeError: 'dict' object has no attribute 'counter'` → Add the `Flow[CounterState]` type parameter
- `history` is empty → Check that you wrote `.append(...)`

```python
class CounterState(BaseModel):
    counter: int = 0
    history: list[str] = []


class CounterFlow(Flow[CounterState]):

    @start()
    def step_one(self):
        self.state.counter += 1
        self.state.history.append("step_one")
        print("step_one ran")

    @listen(step_one)
    def step_two(self):
        self.state.counter += 1
        self.state.history.append("step_two")
        print("step_two ran")
```
