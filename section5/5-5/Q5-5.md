# Section 5 Exercise 5-5 | Calling a Crew from a Flow

## Goal

Complete the practical pattern of **combining Flows and Crews**.
Experience CrewAI's most practical usage pattern: **"the Flow directs the overall traffic, and the Crew is the work team for each stage."**

## What you'll learn in this exercise

### Dividing the roles between Flow and Crew

The Crews (collaborative teams) you built in sections 2-4 and the Flows (controlled flow) from section 5 are really meant to be **used together**.

```
Flow (control tower)
 ├─ Decide on the topic (@start)
 └─ Call the writing Crew (@listen) ← this is where the Crew does its work
```

- **Flow** … controls when, in what order, and under what conditions things run (the control tower)
- **Crew** … carries out the actual work (researching, writing) collaboratively (the work team)

### Kicking off a Crew inside a step

Inside a Flow step (method), you simply build a Crew as usual and call `kickoff`.

```python
@listen(set_topic)
def run_crew(self):
    crew = build_writing_crew()
    result = crew.kickoff(inputs={"topic": self.state.topic})
    self.state.article = str(result)   # save the result into state
    return self.state.article
```

Passing input (`topic`) from the Flow's state to the Crew, and receiving the Crew's output back into state — this round trip is the key to the integration.

## Hints

- The return value of `kickoff` isn't a plain string on its own, so wrap it with `str(result)` before storing it in state

## Common errors

- `KeyError: 'topic'` → check that the key in `inputs` matches `{topic}` inside the Crew
- The article doesn't end up in state → check that you wrote `self.state.article = str(result)`
- `429 RESOURCE_EXHAUSTED` → the Crew makes two LLM calls. Wait a bit and retry
