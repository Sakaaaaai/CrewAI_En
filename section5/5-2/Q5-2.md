# Section 5 Exercise 5-2 | @start and @listen

## Goal

Get started with CrewAI's **Flows**. Write a minimal Flow and confirm that
`@start` and `@listen` **chain steps together in order, with return values flowing from one to the next**.

## What you'll learn in this exercise

### The difference between Crews and Flows

| | Crews | Flows |
|---|---|---|
| Mental model | A team that collaborates autonomously | A workflow with a fixed procedure |
| Best suited for | Creative tasks (e.g. writing articles) | Business processes (branching, state management) |
| Control | Left up to the agents | You design the flow yourself |

Flows are a mechanism for **assembling processing as a flow of steps that you design yourself**. Instead of leaving everything to the LLM, you control the order and branching in code.

### `@start` and `@listen`

```python
from crewai.flow.flow import Flow, start, listen

class GreetingFlow(Flow):

    @start()                       # the step that runs first
    def generate_name(self):
        return "Taro"

    @listen(generate_name)         # runs once generate_name finishes
    def make_greeting(self, name): # <- the previous step's return value comes in as an argument
        return f"Hello, {name}!"
```

- `@start()` … the entry point of the Flow
- `@listen(previous method)` … runs by "listening" for the previous step to complete
- **The previous step's return value becomes the next step's argument** (this is the hand-off mechanism)

### Running it

```python
flow = GreetingFlow()
result = flow.kickoff()   # returns the last step's return value
```

## Hints

- `@start()` has **parentheses** (it's `@start()`, not `@start`)
- The argument to `@listen(generate_name)` is **the method name itself** (not a string)
- The second method takes one argument (`name`) to receive the previous return value

## Success criteria

- [ ] You wrote a 2-step Flow using `@start` and `@listen`
- [ ] You confirmed execution proceeds in the order step 1 -> step 2
- [ ] You confirmed the previous step's return value is passed to the next step

## Common errors

- `TypeError: start() missing` → Add `()` to `@start`
- The second step doesn't run → Check that the method name in `@listen(generate_name)` is correct
- `TypeError: make_greeting() takes 1 ... but 2 given` → Define an argument (`name`) to receive the previous return value
