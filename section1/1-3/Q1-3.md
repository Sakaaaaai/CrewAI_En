# Section 1 Exercise 1-3 | Task and expected_output

## Goal

Define a **Task** and experience how much `description` and `expected_output` shape the quality of the output.
Confirm that with the same Agent and the same instructions, **changing the expected shape of the output (`expected_output`) changes the result**.

## What you'll learn in this exercise

### A Task is "the work you want done"

The Agent you built in 1-2 was a "worker." A Task is the **work order** you hand that worker.

| Attribute | Meaning |
|---|---|
| `description` | What you want done (the body of the instructions) |
| `expected_output` | The shape and granularity of the expected deliverable |
| `agent` | The Agent responsible for this Task |

```python
task = Task(
    description="Write a piece of copy introducing our newly launched hot coffee, 'Morning Cup'.",
    expected_output="a one-line tagline",
    agent=writer,
)
```

### `expected_output` determines quality

`expected_output` specifies "what shape you want the output in." If this is vague, the output will be inconsistent too.

- ❌ `expected_output="something that sounds nice"` → length and format vary wildly
- ✅ `expected_output="an ~100-word introduction that includes 3 emoji"` → consistently hits the mark

**Even with the same description, changing only expected_output changes the deliverable** — this is the key to designing good Tasks.
