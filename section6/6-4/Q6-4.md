# Section 6 Exercise 6-4 | Finishing touches: saving the output and running it

## Goal

The **final finishing touch** for the blog-article-writing pipeline. Add a step that saves the finished article to a Markdown file, and run **topic input → outline → approval → writing Crew → save to Markdown** as **one end-to-end pipeline**.

## What you'll learn in this exercise

### The last piece: leaving behind a deliverable

Up to now, the pipeline has only kept the article in state.
As a final step, add a "save step" so the deliverable is left behind as a file. That completes a genuinely usable app.

```
Outline → approve → writing Crew → [save] → article.md
```

### Chaining onto "after" the writing

The save step only needs to run once the writing (`write_article`) is done, so we chain it with `@listen(write_article)`.

```python
@listen(write_article)
def save_article(self):
    with open("article.md", "w", encoding="utf-8") as f:
        f.write(self.state.article)
    print("-> Saved to article.md")
    return "done"
```

> A Flow is about "stringing steps together into a single business process."
> Saving fits naturally in as just one more step in that chain.

## Common errors

- `article.md` isn't created → check that the method name for `@listen(write_article)` is correct
- Garbled characters in the file → make sure you added `encoding="utf-8"`
- `429 RESOURCE_EXHAUSTED` → outline generation plus a 3-agent Crew means a lot of calls. Wait a bit and retry

## Challenge (optional)

Think about the difference between the `output_file` style (2-4) and the `open(...)` style used here for saving.
- `output_file` … automatic saving per Task (a deliverable from inside the Crew)
- `open(...)` … saving at any timing and with any processing you want, from inside a Flow step
Being comfortable with both gives you much more flexibility in how you save your output.
