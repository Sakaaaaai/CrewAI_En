# Section 6 Exercise 6-2 | Flow skeleton and state design

## Goal

Build the **skeleton** of the capstone exercise, a "blog-article-writing pipeline."
Design the state and **correctly place** `@start` / `@router` / `@listen` to assemble the overall flow.
(The writing itself is filled in in 6-3, and saving in 6-4. This exercise focuses on "design.")

## What you'll learn in this exercise

### Design the big picture first

Rather than jumping straight into the details, **designing the flow and the state first** is the trick to developing with Flows.

```
Topic input → generate an outline → approval check (mock)
                                    ├─ approved → write (6-3)
                                    └─ rejected → stop
```

### Gather "data used across the whole pipeline" into state

Bring together the data that each step reads and writes into a single state.

```python
class BlogState(BaseModel):
    topic: str = "Focus techniques for remote work"   # topic
    outline: str = ""                                  # outline
    article: str = ""                                  # final article (filled in in 6-3)
```

### "Placing" the pieces you've learned

Fit the pieces you've learned so far onto the pipeline.

| Piece | Role | How it's used in this exercise |
|---|---|---|
| `@start` | Entry point | Generates the outline |
| `@router` | Branching | Judges approved / rejected (mock) |
| `@listen("...")` | Route destination | Write if approved, stop if rejected |

> **Mock approval**: In a real system this would be a step where a human gives the OK, but here we substitute a simple rule: "approved if the outline isn't empty" (in production you'd swap this for human input or another kind of check).

## Exercise

Fill in the TODOs in `exercise.py` to complete the pipeline skeleton.

## Success criteria

- [ ] You designed the state for the whole pipeline
- [ ] You placed the flow `@start` → `@router` → `@listen`
- [ ] You confirmed it branches correctly into the approved route

## Common errors

- `state isn't initialized` → check the type parameter `Flow[BlogState]`
- The route doesn't run → cross-check the router's return value against the string in `@listen("...")`
- `429 RESOURCE_EXHAUSTED` → this calls the LLM once for the outline. Wait a bit and retry

```python
class BlogState(BaseModel):
    topic: str = "Focus techniques for remote work"
    outline: str = ""
    article: str = ""


class BlogFlow(Flow[BlogState]):

    @start()
    def create_outline(self):
        self.state.outline = llm.call(
            f"Propose an outline for a blog article titled '{self.state.topic}', as three headings."
        )
        print("=== Outline ===\n", self.state.outline)

    @router(create_outline)
    def approval_gate(self):
        return "approved" if self.state.outline.strip() else "rejected"

    @listen("approved")
    def on_approved(self):
        print("Approved. Proceeding to writing (implemented in 6-3).")
        self.state.article = "(the article will go here)"
        return self.state.article

    @listen("rejected")
    def on_rejected(self):
        print("Stopped because the outline was empty.")
        return "stopped"
```
