# Section 3 Exercise 3-3 | Building Your Own Custom Tool

## Goal

Build a **custom tool** with the `@tool` decorator and equip an agent with it.
Learn that even functionality not covered by the built-in tools can freely become a tool — just write a Python function.

## What you'll learn in this exercise

### Turning a function into a tool with `@tool`

Just add `@tool` to an ordinary Python function, and it becomes a tool the agent can use.

```python
from crewai.tools import tool

@tool("Sales Tax Calculator")
def calc_tax(price: int) -> str:
    """Takes a pre-tax price (an integer) and returns the price with 10% sales tax added"""
    return f"The price including tax is {int(price * 1.1)} yen"
```

### The docstring is the most important part

The `""" ... """` (docstring) is **the explanation that tells the agent "what this tool does."**
If it's vague, the agent can't judge when or how to use the tool.

> The trick is to write the argument's type hint (`price: int`) and the docstring so that **a human can understand them at a glance**. That's exactly what becomes the explanation for the agent too.

### Why turn calculations into a tool

LLMs are good at generating text, but **they're not great at precise calculation or counting characters** (they sometimes get it wrong).
Handing that kind of "exact processing" off to a tool (i.e. ordinary code) makes the agent's answers accurate.

## Hints

- Always write a docstring (an explanation) on the function right after `@tool("tool name")`
- You can count characters with `len(text)`
- Writing "check with the character-count tool as you go" in the description makes it easier for the agent to use the tool
- An LLM's sense of character count isn't perfect, so it may not land on exactly 20 characters every time (the tool's job is to get it close)

## Success criteria

## Common errors

- The tool isn't used -> The docstring is empty or vague. Write clearly what the tool does
- `NameError: count_chars` -> The tool definition (TODO 1) is still commented out
- `TypeError` -> Add a type hint to the argument (`text: str`)

```python
@tool("Character Count")
def count_chars(text: str) -> str:
    """Counts the number of characters in the given text and returns it"""
    return f"{len(text)} characters"


writer = Agent(
    role="Copywriter",
    goal="Write a tagline that is exactly a specified number of characters",
    backstory="You are a professional copywriter who carefully chooses words with an eye on character count.",
    tools=[count_chars],
    llm=llm,
    verbose=True,
)

task = Task(
    description="Write a tagline that is exactly 20 characters long for the new water bottle product, "
                "'Forever Cool Bottle'. "
                "Check the length with the character-count tool as you go, and adjust it to exactly 20 characters.",
    expected_output="A tagline that is exactly 20 characters long",
    agent=writer,
)
```
